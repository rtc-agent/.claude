## Executive Summary

A **critical regression** was found: `.new-message-btn` click handler (`_handleNewBtnClick`) and `_handleLoadMoreClick` were defined as regular async methods but used as Lit event handlers via `@click=${this._handleNewBtnClick}`. In Lit, this pattern does not auto-bind `this`, causing `this` to be `undefined` inside the handler at invocation time. The error is swallowed by the async Promise (unhandled rejection), producing the symptom of "no response" on click. Both handlers were converted to arrow functions. Additionally, `_applyPendingScroll()` called from `updated()` without await was missing error handling for the returned Promise.

### Critical: Event Handler `this` Binding Bug

**Issue 10.1**: `_handleNewBtnClick` defined as regular method, used as event handler
- **File**: `rtc-message-list.ts:560`
- **Severity**: Critical
- **Status**: Fixed
- **Root cause**: In Lit, `@click=${this._handleNewBtnClick}` evaluates `this._handleNewBtnClick` during `render()` to get a method reference, but does NOT bind `this`. When the click fires, `this` is `undefined` inside the regular method. The resulting TypeError is caught by the async Promise, becoming an unhandled rejection that produces no visible error.
- **Fix**: Converted to arrow function (`private _handleNewBtnClick = async () => { ... }`)

**Issue 10.2**: `_handleLoadMoreClick` same `this` binding bug (latent)
- **File**: `rtc-message-list.ts:524`
- **Severity**: High
- **Status**: Fixed
- **Root cause**: Same as 10.1. Not yet reported by users because the load-more button only appears when scrolled near top, which users may not have tested.
- **Fix**: Converted to arrow function (`private _handleLoadMoreClick = async () => { ... }`)
