### 7. 分布式系统风险

**发现的问题**:

- `internal/agent/session_memory_extractor.go:540-576` - 存在轻微竞态窗口：background goroutine 完成提取后可能向已关闭的 session 写入 memories
  - **严重程度**: 建议
  - **修复状态**: ❌ 未修复
  - **说明**: 如果 triggerSessionMemoryExtraction 在 CloseSession 前被调用，goroutine 可能在 session 关闭后完成提取。此时：(1) saveExtractionState 会更新已关闭的 session（无害但浪费）；(2) 新创建的 memories 不会被 DeleteBySession 清理（轻微数据泄漏）。实际影响极小——需要提取恰好在关闭前触发，且泄漏的 memories 量很小。建议在后续迭代中在 save 前检查 session 状态。

**总体评价**: ExtractionState 持久化通过 Session 表字段实现，避免了独立状态存储的一致性风险。并发触发通过 tokenGrowth 阈值天然去重（第二次触发时 growth 不足则跳过）。

## 正确性验证

### ExtractionState 持久化逻辑 ✅
- loadExtractionState 在 goroutine 启动前同步执行，确保 trigger 决策使用最新状态
- saveExtractionState 在 goroutine 内执行，失败不阻塞
- 并发场景：第二次触发在第一次完成前加载旧状态 -> tokenGrowth 不足 -> 自动跳过（天然去重）

### tokenGrowth 计算 ✅
- state == nil 时：tokenGrowth = currentTokens（首次提取，全量视为增长）
- state != nil 时：tokenGrowth = currentTokens - state.LastTokenCount（精确增量）
- 测试覆盖了 nil state、有 state、growth 不足、growth 充足等场景

### DeleteBySession 事务 ✅
- CloseSession：在 RunAndPublish 事务内调用，失败仅 Warn 不阻塞
- stopSubAgent：在每次 session 关闭的 RunAndPublish 事务内调用

### 语言检测 ✅
- 多策略检测：显式指令匹配（containsCJKDirective）+ 隐式 CJK 内容比例（containsChineseHint）
- 30% CJK 字符阈值合理，避免将含少量中文的英文 prompt 误判为中文
- 测试覆盖了中英文混合、纯英文、纯中文、空字符串等场景

## 遗留问题

1. **Background goroutine 竞态窗口**（建议级别）：extraction goroutine 可能在 session 关闭后完成写入。影响极小，建议在后续迭代中在 save 前检查 session 状态，或通过 context 取消信号通知 goroutine。

2. **SessionMemory.DeletedAt 字段为死代码**（未在本次审查中修复）：项目所有 model 使用 `*time.Time` 而非 `gorm.DeletedAt`，导致 GORM 不会自动激活软删除。`DeletedAt` 列在数据库中存在但从未被写入。建议后续统一决策：要么改用 `gorm.DeletedAt` 启用真正的软删除，要么移除该字段减少存储开销。

## 优点

1. **Panic Recovery 设计优秀**：使用 `context.Background()` 确保日志可写，defer 位置正确
2. **State 持久化方案简洁**：复用 Session 表字段，避免额外状态存储
3. **并发安全天然保证**：tokenGrowth 阈值检查天然防止重复提取
4. **测试覆盖全面**：96 个测试用例，覆盖正常路径、边界条件、错误传播
5. **语言检测策略合理**：多策略组合，CJK 比例检测避免误判
6. **DeleteBySession 放置正确**：两个关闭路径（CloseSession、stopSubAgent）均已覆盖
