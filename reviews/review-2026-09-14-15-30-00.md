## 架构一致性审查

### 与 `internal/model/session_memory.go` / `user_memory.go` 的对比

| 维度 | 现有模型 | 新 Memory 模型 | 一致性 |
|------|----------|---------------|--------|
| UUID 生成 | `uuid.NewV7()` in BeforeCreate | `uuid.NewV7()` in BeforeCreate | ✅ 一致 |
| 软删除 | `*time.Time` | `gorm.DeletedAt` | ⚠️ 改进（自动过滤） |
| Tags 类型 | `StringArray` + `type:text[]` | `model.StringArray` + `type:jsonb` | ⚠️ 存储格式不同 |
| Metadata 类型 | `JSONB[any]` | `model.JSONBString` | ⚠️ 类型不同 |
| 验证逻辑 | 无 | 有 `Validate()` | ✅ 新增能力 |
| Repository 位置 | `internal/repo/` | `pkg/memory/`（接口定义） | ✅ 依赖倒置 |

### Tags 字段存储格式偏差

- 设计文档和 UserMemory 使用 `type:text[]`（PostgreSQL 原生数组）
- 新 Memory 使用 `type:jsonb`（JSON 数组）
- 影响：JSONB 查询更灵活（`?`, `?|`, `@>` 操作符），但与现有模式不一致
- **建议**: 如果选择 JSONB，需在迁移文档中明确说明

### DeletedAt 字段类型改进

- 现有模型使用 `*time.Time`，GORM 不自动过滤软删除记录
- 新模型使用 `gorm.DeletedAt`，GORM 自动在所有查询中添加 `deleted_at IS NULL`
- **评价**: 这是一个改进，但需确保与现有软删除行为兼容
