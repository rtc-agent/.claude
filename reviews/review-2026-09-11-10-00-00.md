### 7. 分布式系统风险

- **SRem 返回值误用导致 batch 永远无法完成** -- submitrtcresult.go:307-317
  - 严重程度: 严重 (功能完全失效)
  - 修复状态: ✅ 已修复
  - 修复说明: Redis SRem 返回被移除的成员数(0或1)。原代码 if remaining > 0 在正常完成时(SRem返回1)总是 true，导致函数提前返回，batch completion 永远无法触发。使用 Lua 脚本在 SRem 后调用 SCARD 获取真正的剩余数量。
- **多个 Redis 操作非原子性** -- 原代码 Exists + HSet + Expire + SRem 是 4 个独立操作
  - 严重程度: 严重 (TOCTOU 竞态)
  - 修复状态: ✅ 已修复
  - 修复说明: 合并为 Lua 脚本 BatchComplete，保证 EXISTS + HSET + EXPIRE + SREM + SCARD 原子执行
- **resultsKey 缺少 TTL 导致潜在内存泄漏** -- 原代码在 Lua 脚本化时丢失了 Expire 调用
  - 严重程度: 警告 | 修复: ✅ 在 Lua 脚本中添加 EXPIRE 调用，通过 ARGV[3] 传入 TTL

**总体评价**: 核心分布式风险已全部修复。Lua 脚本确保了原子性，SCARD 替代了误用的 SRem 返回值。
