## 变更概述

### Commit 586ec02: 重写 SigV4 验证使用 AWS SDK

**核心变更**：将手动的 canonical request / string-to-sign 计算替换为 AWS SDK v4 的 `SignHTTP` 方法，确保与所有 AWS SDK 客户端 100% 兼容。

**关键修复**：
- [P1/Critical] `LookupCredential` 缓存未命中时返回加密后的 secret key（导致首次请求签名验证必定失败）
- 处理 Go HTTP server 的特殊行为（Content-Length、Transfer-Encoding 被解析后从 Header 中移除）
- 移除代理添加的 headers（Connection、X-Forwarded-For 等），避免签名不匹配

### Commit 96aeed7: 解决签名验证细节问题

**核心变更**：修复 Accept-Encoding header 导致签名不匹配的问题。

**关键修复**：
- [P1] 客户端和服务端统一处理 Accept-Encoding header（Go HTTP client 自动添加 `gzip`）
- 修复测试中 header 设置顺序（先设置所有 headers，再签名）
- 修复 `newSignedS3Request` 传递空 session token 的问题（改为传递真实 token）

### 5. 安全问题

**观察结果**:

- **[信息] `hmac.Equal` 常量时间比较** — `sigv4.go:121,170`
  - 签名比较使用 `hmac.Equal`，防止时序攻击。正确。

- **[信息] 错误信息不泄露内部细节** — `sigv4.go:62`
  - Scope 不匹配时返回 `ErrInvalidSignature`（非描述性错误），防止攻击者推断 scope 格式。正确。

- **[信息] 15 分钟时间窗口** — `sigv4.go:73`
  - 使用 `verifyTimestamp(amzDate, 15*time.Minute)` 防止重放攻击。符合 AWS SigV4 标准。

- **[信息] `host` 必须在 SignedHeaders 中** — `sigv4.go:39-55`
  - 强制要求 `host` 在签名 header 中，防止 host header 篡改。正确。

- **[信息] 代理 header 清理** — `sigv4.go:88-90`
  - 重新签名前移除 `Connection`、`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Real-Ip`。防止代理注入的 header 干扰签名。正确。

- **[信息] 凭证缓存加密** — `oss3_credential_cache.go`
  - SecretAccessKey 在 Redis 中以加密形式存储。缓存命中时解密。正确。

**总体评价**: 安全意识强。所有关键安全点都已覆盖。

### 6. 错误处理

**发现的问题**:

- **[建议] `SignS3Request` 忽略 `SignHTTP` 错误** — `sigv4.go:517`
  - **严重程度**: 建议
  - **修复状态**: ❌ 未修复（设计决策）
  - **说明**: `_ = signer.SignHTTP(...)` 静默忽略签名错误。作为导出函数（用于测试和客户端 SDK），忽略错误可能导致难以调试的签名不匹配。但考虑到：(1) 当前仅用于测试辅助；(2) SignHTTP 在参数正确时几乎不会失败；(3) 修改签名会破坏调用方。决定保持现状。

- **[信息] `LookupCredential` 区分 "not found" 和 DB 错误** — `oss3_credential_cache.go:76-81`
  - `gorm.ErrRecordNotFound` 返回 `nil, nil`（凭证不存在），其他错误返回 `nil, err`（传播给调用方返回 500）。正确。

- **[信息] 缓存解密失败时主动失效** — `oss3_credential_cache.go:51-58`
  - 如果缓存中的加密数据无法解密，主动删除缓存并回退到 DB。防止永久使用损坏的缓存数据。正确。

**总体评价**: 错误处理规范。边界情况（DB 错误 vs 未找到、缓存损坏）都正确处理。
