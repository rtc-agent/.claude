### 7. 分布式系统风险

**发现的问题**: 无

**逐项分析**:

**4.1 removedManagers 自清理 goroutine**:
- **identity check** (`r.removedManagers[sessionID] == mgr`) 是并发安全的关键。它确保只有当 map 中的值仍然是"我们移除的那个 mgr"时才删除。如果另一个 goroutine 已经用同一个 sessionID 创建了新的 manager 并触发了新的 Remove，identity check 会阻止误删新 manager 的条目。
- **goroutine 数量**: 每个 Remove/Replace 操作产生一个 goroutine，其生命周期 = 等待 `Done()` channel 关闭的时间。由于 `SessionTurnManager.cleanup` 由 `sync.Once` 保证执行且总会 `close(mgr.done)`，goroutine 不会永久存活。数量受并发 Replace 频率约束，是有界的。
- **锁竞争**: goroutine 持有 `r.mu.Lock()` 的时间极短（一次 map 查找 + 可能的删除），不会成为瓶颈。

**4.2 TopicBroker.closed**:
- `closed.Store(true)` 在 `pubSubMu` 锁内执行，`ensurePubSubClient` 先 `closed.Load()` 再访问 `pubSubClient`。时序正确：先标记关闭 → 再清理资源。
- 如果 `Subscribe` 在 `Close` 后调用：`ensurePubSubClient` 返回 error → `Subscribe` 返回 error → 不会创建新的 `DedicatedClient`。

**4.3 CleanupSession**:
- 调用时机在 `stopActiveTurns` 之后的异步 goroutine 中。此时 session 已标记为 Closed（DB 层），新的 turn 不会被创建。理论上存在微小的竞争窗口（session 刚标记 Closed 但 turn 仍在启动），但最坏情况是新的 activated entries 被创建后未被清理。由于 session 已关闭，后续不会有新的 `DetectAndInject` 调用，不会产生无限增长。
- `CommandRegistry != nil` 检查防止了 nil panic (`action.closesession.go:107`)。

**4.4 DualBroker.channelTypes**:
- `Unsubscribe` 在底层 unsubscribe 成功后才 `Delete` 条目，顺序正确 (`dual_broker.go:144-145`)。
- `Close()` 中的 `Range + Delete` 确保清理所有残留条目 (`dual_broker.go:361-364`)。
- sync.Map 的并发安全性由 Go 标准库保证。

**4.5 Throttle.Stop()**:
- `Stop()` 持有 `t.mu` 锁，timer 回调也需要 `t.mu` 锁，因此不存在竞争。
- `timer.Stop()` 返回 false 表示 timer 已过期或已停止。即使 timer 回调已在等待锁，`Stop()` 先清理 maps → 回调获取锁后发现 key 不存在 → 成为 no-op。
- 关键正确性：回调中 `delete(t.timers, key)` 对已删除的 key 是安全的（map delete 对不存在的 key 是 no-op）。

**总体评价**: 优秀。所有修复的并发安全性都经过了仔细推敲。

## 修复详情：Throttle.Stop() 调用方缺失

**问题**: `Throttle.Stop()` 方法已正确实现，但没有任何代码调用它。`helpers.tokenUpdateThrottle` 是一个进程级单例，其 `Stop()` 应该在进程关闭时被调用。

**风险分析**:
- `helpers` 是进程级单例（通过 Wire 注入），生命周期 = 进程生命周期
- Throttle 内的 timer 会在 500ms 内自动触发并自清理，正常情况下不会泄漏
- pending functions 的引用持有时间最多 500ms
- 但在 graceful shutdown 时，不调用 `Stop()` 会导致 pending closures 无法被 GC 及时回收

**修复方案**: 在 `helpers` 上添加 `Close()` 方法，调用 `tokenUpdateThrottle.Stop()`。

**修复文件**: `internal/agent/agent.go`
